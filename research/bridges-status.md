# GROK-6 — Bridge and cross-chain status sweep

**Checked:** 2026-11-24 (America/Chicago)
**Checked by:** Grok swarm (GROK-6, Bob Research)
**Scope:** Every way I could find to move value onto (or off) Midnight: the official Cardano→Midnight NIGHT bridge, cNgD, VIA Labs, Pintent, Sig Network, the Capacity Exchange, Glacier Drop redemption, and the big general-purpose bridges (LayerZero, Wanchain, Wormhole, Axelar, Rosen). This closes the "General-purpose bridges" gap in `research/ecosystem-directory.md`.

## Method and limits

I opened every URL in the tables on 2026-11-24, using WebFetch for page text and `curl` for HTTP status. Where `curl` got HTTP 429 from `midnight.network` / `docs.midnight.network` (Vercel rate limit, same as GROK-1), I read the page through WebFetch, which returned it.

I did **not** connect a wallet, sign anything, move funds, request faucet tokens, create an API key or sign up for anything. A bridge can't be *used* without a wallet signature, so following the board rule, **nothing below is labelled "live (verified usable)"**. When a route has public, read-only evidence that it is carrying real transfers (for example, an explorer API), I mark it **"live per public evidence, not used by me"** and say exactly what I saw.

**Network labels:** Preview and Preprod are **testnets**. Stagenet is a permissioned test network. Mainnet is production.

**Stack pins (current, ledger 9):** Compact toolchain **0.36.1**, Midnight.js **5.0.1**, Wallet SDK **2.0.1**, DApp Connector API **4.1.0**, proof server **9.0.2**, indexer **4.4.101** (see `research/stack-versions.md`). I treat projects that pin Ledger 8-era tooling as stale, not current.

It misses VIA Labs' USDM route, which public evidence shows running on mainnet. I am not editing the directory in this PR; that correction should be a follow-up once this one is reviewed.

## What the gap means for someone moving value onto Midnight today

As of 2026-11-24:

- **NIGHT stays on Cardano.** The official cNIGHT→mNIGHT bridge is in the ledger 9 node but switched off pending governance, and the way back (Midnight→Cardano) is a later stage with no date. Anyone offering to "bridge your NIGHT to Midnight" today is either ahead of the official rollout or wrong. Treat it as a red flag.
- **To *use* Midnight with Cardano NIGHT, you don't bridge.** You register cNIGHT through cNgD (or a wallet such as 1AM or Gero that does the same mapping), and it generates DUST on Midnight. That gives you fee capacity, not spendable value. Allow about 12 hours for the registration to land.
- **The one cross-chain value route with public evidence of mainnet traffic is VIA Labs' USDM.** It runs Cardano↔Midnight, about 50 min in and about 20 min out. It is a stablecoin, **unshielded** on Midnight by design, and the route trusts VIA's 2-of-3 signer set plus approved relayers, because Midnight can't verify signatures on-chain yet. Anyone holding ETH, SOL, BTC or BNB first has to get to Cardano USDM. No direct route from those chains into Midnight was found working.
- **Fees can be abstracted, not value.** The Capacity Exchange and DUST sponsorship let apps cover fees or take USDM for them. That removes the "need DUST first" wall but doesn't bring assets in.
- **Everything else is testnet or announcement:** Pintent (stale Preprod demo), Sig Network (Stagenet/Preview, mainnet placeholders), LayerZero (approved Feb 2026, no deployment found), and the roadmap's Q4 2026 "new bridges". Wanchain carries cNIGHT between Cardano and BNB Chain, never onto Midnight, and was exploited in July 2026.
- **For our builds:** a Kshot Applications dApp that wants users bringing value should assume **USDM via VIA** as the only in-route today, show the NIGHT bridge as "coming, not live", and lean on DUST sponsorship or the Capacity Exchange for onboarding. Any tip or payment flow should keep taking ADA on Cardano and the Midnight shielded address directly, not promise a bridge.
